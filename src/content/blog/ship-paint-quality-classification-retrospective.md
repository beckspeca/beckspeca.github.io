이미지 분류 성능을 높이려 할 때는 더 큰 모델, 더 높은 해상도, 앙상블 같은 방법이 먼저 떠오른다. 이번 선박 도장 품질 분류 대회에서도 비슷한 순서로 접근했다.

하지만 가장 큰 개선을 만든 것은 새로운 기법이 아니었다. 학습 로그를 다시 확인하고 나서야 베이스라인이 **단 1 epoch만 학습된 모델**이라는 사실을 발견했다.

이 글은 그 단순한 설정 하나를 놓친 채 여러 실험을 돌아간 과정과, Public Macro F1을 **0.949에서 0.9688까지** 높이며 얻은 교훈을 정리한 회고다.

| 단계 | Public Macro F1 |
| --- | ---: |
| ResNet18 베이스라인 | 0.949 |
| 3개 모델 앙상블 | 0.919 |
| 2개 모델 앙상블 | 0.919 |
| 검증된 설정으로 복귀 | 0.956 |
| 15 epoch + 2개 모델 앙상블 | **0.9688** |

## 1. 문제 정의: 모든 클래스를 고르게 맞혀야 했다

대회의 목표는 선박 도장 표면 이미지를 다섯 가지 품질 상태로 분류하는 것이었다.

| 클래스 | 의미 |
| --- | --- |
| 도막떨어짐 | 도막이 벗겨진 결함 |
| 스크래치 | 표면이 긁힌 결함 |
| 부풀음 | 도막 아래에 기포가 생겨 부풀어 오른 결함 |
| 이물질포함 | 도막에 이물질이 섞인 결함 |
| 양품 | 결함이 없는 정상 표면 |

평가 지표는 클래스별 F1을 동일한 비중으로 평균하는 **Macro F1**이었다. 데이터 수가 많은 클래스를 잘 맞히는 것만으로는 높은 점수를 얻기 어려운 구조다.

실제로 부풀음은 4,680장, 이물질포함은 4,786장이었다. 도막떨어짐 16,037장과 스크래치 16,376장보다 약 3.4배 적었다. 따라서 소수 클래스의 recall이 낮아지면 전체 점수도 직접 영향을 받는다.

이번 프로젝트의 핵심 질문은 다음과 같았다.

> 데이터가 불균형한 5개 클래스에서 소수 결함을 놓치지 않으면서 Macro F1을 어떻게 높일 수 있을까?

## 2. 시작점: ResNet18과 0.949

첫 모델은 ImageNet 사전학습 가중치를 사용한 ResNet18이었다. 입력 이미지는 224×224로 맞추고 단일 모델로 예측했다.

Public Macro F1은 **0.949**였다. 출발점으로는 나쁘지 않았지만, 어떤 클래스에서 오류가 발생하는지와 현재 학습이 충분한지는 아직 확인하지 않은 상태였다.

돌이켜보면 이때 먼저 해야 했던 일은 복잡한 모델을 추가하는 것이 아니라 다음 항목을 고정하는 일이었다.

- 학습 epoch와 조기 종료 조건
- 학습과 추론의 이미지 해상도
- 단일 모델의 클래스별 성능
- 동일한 검증 데이터와 평가 코드

이 기준을 충분히 고정하지 않은 채 다음 실험으로 넘어가면서 비교의 기준도 함께 흔들렸다.

## 3. 추가 데이터를 찾았지만 사용할 이미지는 없었다

먼저 원본 데이터에 대회 학습 데이터로 선택되지 않은 이미지가 더 있는지 확인했다. 확인 결과 `selected_5class`는 원본 Training 데이터 전체와 이미지 수가 정확히 같았고, `Other` 폴더에는 메타데이터만 있을 뿐 실제 이미지는 없었다.

추가 학습 데이터를 확보하는 방법은 사용할 수 없었다.

대신 원본 메타데이터에는 대회의 다섯 클래스 외에도 용접손상, 균열, 도막분리, 워터스포팅, 핀홀, 흐름 같은 불량 유형이 존재했다. 이는 표면만 보고 양품과 불량을 구분하는 일이 생각보다 단순하지 않으며, 시각적으로 비슷한 결함 사이의 경계도 모호할 수 있다는 힌트였다.

결국 주어진 데이터를 더 안정적으로 학습하고, 클래스별 오류를 줄이는 방향에 집중해야 했다.

## 4. 고해상도 실험에서 만난 ViT 입력 크기 문제

스크래치의 가는 선이나 부풀음의 작은 기포처럼 미세한 특징을 더 잘 포착하기 위해 입력 해상도를 224에서 384로 높이려 했다.

ResNet은 `AdaptiveAvgPool`을 사용하므로 입력 크기가 바뀌어도 처리할 수 있었다. 반면 `torchvision`의 ViT-B/16은 바로 실행되지 않았다.

```text
AssertionError: Wrong image height! Expected 224 but got 384!
```

ViT 내부에서 입력 크기를 224로 확인하고 있었기 때문이다. positional embedding만 보간해서는 충분하지 않았고, 모델이 입력 크기를 검사할 때 사용하는 `image_size` 속성도 함께 바꿔야 했다.

```python
model.image_size = IMAGE_SIZE

pos_embed = model.encoder.pos_embedding
cls_token = pos_embed[:, :1, :]
spatial = pos_embed[:, 1:, :]

side = int(spatial.shape[1] ** 0.5)
grid = IMAGE_SIZE // model.patch_size
num_patches = grid * grid

spatial_4d = spatial.permute(0, 2, 1).reshape(1, -1, side, side)
resized = torch.nn.functional.interpolate(
    spatial_4d,
    size=(grid, grid),
    mode='bilinear',
    align_corners=False,
)

model.encoder.pos_embedding = nn.Parameter(
    torch.cat(
        [cls_token, resized.reshape(1, -1, num_patches).permute(0, 2, 1)],
        dim=1,
    )
)
```

이 실험에서 사전학습 모델의 입력 크기를 바꿀 때는 가중치뿐 아니라 **모델 내부의 입력 검증 로직과 위치 정보 표현까지** 함께 확인해야 한다는 점을 배웠다.

그러나 입력 오류를 해결했다는 것과 새로운 해상도에서 성능이 보장된다는 것은 별개의 문제였다.

## 5. 앙상블이 점수를 0.919로 떨어뜨린 이유

다음으로 CNN, ResNet18, ViT-B/16 세 모델의 확률을 같은 비중으로 평균하는 soft voting 앙상블과 좌우 반전 TTA를 적용했다.

| 모델 | Validation F1 |
| --- | ---: |
| CNN | 0.3333 |
| ResNet18 | 0.9469 |
| ViT-B/16 | 0.9188 |

결과는 기대와 반대였다. Public 점수가 **0.919**로 크게 떨어졌다.

첫 번째 원인은 앙상블 구성원의 품질이었다. F1이 0.3333인 CNN은 사실상 분류에 실패한 모델이었지만 다른 두 모델과 같은 3분의 1 비중을 받았다. 평균을 내는 과정에서 좋은 모델의 확률까지 흐려졌다.

CNN을 제외하고 ResNet18과 ViT-B/16만 남겼지만 점수는 여전히 0.919였다. 이번에는 다른 문제가 있었다. 두 체크포인트는 224 해상도로 학습했는데 추론만 384 해상도로 수행하고 있었다.

정리하면 두 번의 실패 원인은 서로 달랐다.

1. 첫 앙상블은 성능이 낮은 CNN이 예측을 오염시켰다.
2. 두 번째 앙상블은 학습과 추론의 입력 해상도가 달랐다.

앙상블과 TTA 자체가 실패한 것이 아니라, 그 기법을 적용하기 위한 기본 조건을 맞추지 못한 실험이었다.

## 6. 검증된 설정으로 돌아가 0.956을 확보했다

문제를 분리하기 위해 가장 단순하고 검증된 조합으로 돌아갔다.

```text
입력 해상도: 224×224
모델: ResNet18 단일 모델
학습·추론 해상도: 동일
```

Public Macro F1은 **0.956**으로 회복됐다. 처음의 0.949보다 소폭 높은 점수였다.

이 시점의 의미는 단순히 점수가 돌아왔다는 데 있지 않았다. 이후 실험이 좋아졌는지 나빠졌는지를 판단할 수 있는 안정적인 기준을 다시 확보했다는 점이 중요했다.

## 7. 로그에서 발견한 `QUICK_RUN=True`

0.956 모델의 학습 로그를 다시 확인하다가 결정적인 설정을 발견했다.

```python
QUICK_RUN = True
```

개발 과정에서 코드가 정상적으로 실행되는지만 빠르게 확인하려고 만든 옵션이었다. 이 옵션 때문에 모델은 단 1 epoch만 학습되고 있었다.

고해상도, 앙상블, TTA를 시도하는 동안 정작 베이스라인 학습이 끝까지 진행됐는지는 확인하지 않았던 것이다. 1 epoch만으로 0.956이 나왔다면, 이 결과는 성능의 한계가 아니라 추가 학습의 가능성을 보여주는 신호에 가까웠다.

설정을 다음과 같이 바꿨다.

```python
QUICK_RUN = False
FULL_EPOCHS = 15
MODELS_TO_RUN = ['resnet18', 'vit_b_16']
```

성능이 낮았던 CNN은 제외하고 ResNet18과 ViT-B/16을 같은 224 해상도와 같은 학습 조건으로 다시 학습했다.

ResNet18은 9 epoch에서 Validation F1 **0.9912**를 기록했고, 13 epoch에서 조기 종료됐다. ViT-B/16도 첫 epoch부터 Validation F1 0.9824로 출발했다.

학습이 끝난 두 체크포인트에 soft voting과 좌우 반전 TTA를 적용한 결과 Public Macro F1은 **0.9688**까지 올랐다.

```text
0.949  ResNet18 베이스라인
  ↓
0.919  조건을 통제하지 못한 앙상블
  ↓
0.956  224 해상도 + ResNet18로 복귀
  ↓
0.9688  15 epoch + ResNet18·ViT 앙상블
```

가장 큰 차이를 만든 것은 새로운 모델을 추가한 일이 아니라, **각 모델을 충분히 학습하고 동일한 조건에서 비교한 것**이었다.

## 8. 혼동행렬에서 찾은 남은 병목

0.9688 모델의 혼동행렬을 확인하자 두 가지 오류가 반복됐다.

| 실제 클래스 | 예측 클래스 | 해석 |
| --- | --- | --- |
| 스크래치 | 도막떨어짐 | 시각적으로 비슷한 결함 사이의 구분 실패 |
| 부풀음 | 양품 | 작은 결함을 놓쳐 소수 클래스 recall 하락 |

특히 부풀음을 양품으로 판단하는 오류는 Macro F1에 불리하다. 데이터가 적은 클래스의 recall이 낮아지지만 Macro F1에서는 각 클래스가 동일한 비중을 갖기 때문이다.

이 분석을 바탕으로 다음 실험에서는 기본 역빈도 가중치보다 소수 클래스의 손실을 더 크게 반영하도록 가중치를 강화했다.

```python
# 기본 역빈도 가중치
class_weights = total / (n_classes * counts)

# 소수 클래스 가중치 강화
WEIGHT_POWER = 1.5
class_weights = (total / (n_classes * counts)) ** WEIGHT_POWER
```

| 클래스 | 기본 가중치 | 강화 가중치 |
| --- | ---: | ---: |
| 부풀음 | 2.50 | **3.95** |
| 이물질포함 | 2.44 | **3.82** |
| 도막떨어짐 | 0.73 | 0.62 |
| 스크래치 | 0.71 | 0.60 |
| 양품 | 0.71 | 0.59 |

다수 클래스 대비 소수 클래스의 상대적 가중치는 약 3.4배에서 6.3배로 커진다. 다만 이 설정의 최종 제출 성능은 아직 확인 중이므로, **0.9688은 기존 2개 모델 앙상블의 확정 결과**이고 가중치 강화는 다음 실험으로 구분했다.

## 9. 이번 프로젝트에서 배운 것

### 충분히 학습된 단일 모델이 먼저다

앙상블이나 고해상도 실험보다 먼저 단일 모델의 학습이 충분한지 확인해야 한다. 베이스라인이 안정적이어야 이후 실험의 효과도 정확히 비교할 수 있다.

### 앙상블은 구성원의 약점을 지워주지 않는다

성능이 낮은 모델에 동일한 가중치를 주면 오히려 전체 예측이 나빠질 수 있다. 앙상블 여부보다 어떤 모델을 어떤 비중으로 결합할지가 중요하다.

### 학습과 추론 조건은 같아야 한다

224 해상도로 학습한 체크포인트를 384 해상도 추론에 그대로 사용하는 것은 공정한 비교가 아니었다. 입력 크기를 바꾸려면 그 조건으로 다시 학습하고 검증해야 한다.

### Macro F1에서는 클래스별 오류를 봐야 한다

전체 점수 하나만 보면 부풀음을 양품으로 놓치는 문제가 가려진다. 클래스별 precision과 recall, 혼동행렬을 함께 봐야 다음 실험의 방향을 정할 수 있다.

### 빠른 실행 옵션과 본 학습을 명확히 분리해야 한다

`QUICK_RUN`은 파이프라인 확인에는 유용하지만 그 결과를 충분히 학습된 모델의 성능으로 오인하면 안 된다. 실행 모드가 로그와 결과 파일에 명확하게 남도록 만드는 것도 실험 관리의 일부다.

## 10. 다시 시작한다면

같은 문제를 다시 푼다면 다음 순서로 진행할 것이다.

1. 224 해상도의 ResNet18 단일 모델을 충분히 학습한다.
2. 고정된 검증 데이터에서 클래스별 F1과 혼동행렬을 기록한다.
3. ViT를 같은 조건으로 학습해 단일 모델 성능을 비교한다.
4. 검증 성능과 오류 상관관계를 확인한 뒤 앙상블 후보를 고른다.
5. 소수 클래스 recall을 기준으로 가중치와 리샘플링을 비교한다.
6. 마지막으로 384 해상도를 별도의 학습 실험으로 검증한다.

실험을 이 순서로 진행하면 각 변경이 점수에 어떤 영향을 주었는지 설명하기 쉽고, 실패했을 때 돌아갈 기준도 분명해진다.
