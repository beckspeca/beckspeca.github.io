머신러닝 분류 모델을 평가할 때 가장 먼저 확인하는 지표는 보통 **정확도(Accuracy)**다.

정확도는 의미가 직관적이고 계산도 간단하다. 모델이 전체 데이터 중 몇 개를 올바르게 예측했는지 보여주기 때문이다.

하지만 정확도가 높다고 해서 반드시 좋은 모델인 것은 아니다. 특히 클래스별 데이터 수가 크게 다른 **불균형 데이터**에서는 정확도가 모델의 실제 성능을 왜곡할 수 있다.

이번 글에서는 다음 내용을 알아본다.

- 정확도가 무엇인지
- 정확도가 높아도 모델을 신뢰할 수 없는 이유
- 불균형 데이터에서 발생하는 문제
- 혼동행렬과 다른 평가 지표가 필요한 이유
- scikit-learn으로 여러 평가 지표를 확인하는 방법

## 1. 정확도란 무엇인가?

정확도는 전체 데이터 중 모델이 올바르게 예측한 데이터의 비율이다.

```text
정확도 = 올바르게 예측한 데이터 수 / 전체 데이터 수
```

예를 들어 100개의 데이터를 분류했는데 모델이 90개를 올바르게 예측했다면 정확도는 90%다.

```text
Accuracy = 90 / 100 = 0.9
```

Python에서는 scikit-learn의 `accuracy_score()`를 사용해 정확도를 계산할 수 있다.

```python
from sklearn.metrics import accuracy_score

y_true = [0, 1, 1, 0, 1]
y_pred = [0, 1, 0, 0, 1]

accuracy = accuracy_score(y_true, y_pred)

print(accuracy)
```

실행 결과는 다음과 같다.

```text
0.8
```

전체 5개 중 4개를 올바르게 예측했으므로 정확도는 80%다. 이처럼 정확도는 모델의 전체 예측 결과를 하나의 숫자로 표현할 수 있다는 장점이 있다.

하지만 정확도는 **어떤 클래스를 틀렸는지**는 알려주지 않는다.

## 2. 정확도 99%인 모델은 좋은 모델일까?

질병 진단 데이터를 예로 들어 보자. 전체 환자 1,000명 중 정상 환자가 990명이고 질병 환자가 10명이라고 가정한다.

| 실제 상태 | 데이터 개수 | 비율 |
| --- | ---: | ---: |
| 정상 | 990명 | 99% |
| 질병 | 10명 | 1% |
| 합계 | 1,000명 | 100% |

이 데이터에서 모델이 모든 환자를 `정상`이라고 예측한다고 가정해 보자.

```text
정상 환자 990명 → 정상으로 예측
질병 환자 10명 → 정상으로 예측
```

모델은 정상 환자 990명을 모두 맞혔으므로 정확도는 다음과 같다.

```text
Accuracy = 990 / 1,000 = 0.99
```

정확도는 99%다. 숫자만 보면 매우 뛰어난 모델처럼 보인다. 하지만 이 모델은 질병 환자 10명을 한 명도 찾아내지 못했다.

질병 진단 모델의 목적이 환자를 찾아내는 것이라면, 이 모델은 사실상 아무런 역할을 하지 못한 것이다.

```text
정확도: 99%
질병 환자 탐지: 0명
```

따라서 정확도 99%라는 숫자만 보고 모델의 성능이 좋다고 판단하면 안 된다.

## 3. 정확도가 높게 나오는 이유

불균형 데이터에서는 특정 클래스의 데이터가 압도적으로 많다. 앞의 예에서는 정상 클래스가 전체 데이터의 99%를 차지한다.

모델이 데이터가 많은 정상 클래스만 반복해서 예측해도 대부분의 데이터를 맞힐 수 있다.

```text
모든 데이터를 정상으로 예측
→ 정상 데이터 990개 정답
→ 질병 데이터 10개 오답
→ 전체 정확도 99%
```

모델의 관점에서는 소수 클래스인 질병 데이터를 포기하더라도 전체 오답 수가 많지 않다. 이 때문에 모델이 다수 클래스에 편향될 수 있다.

```text
불균형한 데이터
→ 다수 클래스 중심으로 학습
→ 전체 정확도 상승
→ 소수 클래스 예측 실패
```

즉, 정확도는 전체적으로 몇 개를 맞혔는지는 보여주지만 클래스별 성능 차이는 제대로 보여주지 못한다.

## 4. 혼동행렬로 예측 결과 확인하기

정확도의 한계를 보완하려면 **혼동행렬(Confusion Matrix)**을 확인해야 한다.

혼동행렬은 실제값과 예측값의 조합을 네 가지로 구분한다.

| 구분 | 의미 |
| --- | --- |
| TP | 실제 양성을 양성으로 올바르게 예측 |
| TN | 실제 음성을 음성으로 올바르게 예측 |
| FP | 실제 음성을 양성으로 잘못 예측 |
| FN | 실제 양성을 음성으로 잘못 예측 |

질병 진단을 기준으로 해석하면 다음과 같다.

- **TP**: 질병 환자를 질병으로 예측
- **TN**: 정상 환자를 정상으로 예측
- **FP**: 정상 환자를 질병으로 잘못 예측
- **FN**: 질병 환자를 정상으로 잘못 예측

앞의 모델은 모든 환자를 정상으로 예측했다. 따라서 혼동행렬은 다음과 같이 나타난다.

```text
TN = 990
FP = 0
FN = 10
TP = 0
```

표로 표현하면 다음과 같다.

|  | 정상으로 예측 | 질병으로 예측 |
| --- | ---: | ---: |
| 실제 정상 | 990 | 0 |
| 실제 질병 | 10 | 0 |

정확도만 보면 99%지만 혼동행렬을 보면 질병 환자를 한 명도 찾아내지 못했다는 사실을 바로 확인할 수 있다.

Python에서는 다음과 같이 혼동행렬을 계산한다.

```python
from sklearn.metrics import confusion_matrix

y_true = [0] * 990 + [1] * 10
y_pred = [0] * 1000

cm = confusion_matrix(y_true, y_pred)

print(cm)
```

실행 결과는 다음과 같다.

```text
[[990   0]
 [ 10   0]]
```

scikit-learn의 이진 분류 혼동행렬은 다음 순서로 출력된다.

```text
[[TN, FP],
 [FN, TP]]
```

## 5. Precision과 Recall이 필요한 이유

불균형 데이터에서는 정확도와 함께 **정밀도(Precision)**와 **재현율(Recall)**을 확인해야 한다.

### 5.1 정밀도

정밀도는 모델이 양성이라고 예측한 데이터 중 실제로 양성인 데이터의 비율이다.

```text
Precision = TP / (TP + FP)
```

질병 진단에서는 다음 질문에 해당한다.

> 모델이 질병이라고 예측한 사람 중 실제 질병 환자는 얼마나 되는가?

정밀도가 낮으면 정상 환자를 질병으로 잘못 판단하는 경우가 많다는 의미다.

### 5.2 재현율

재현율은 실제 양성 데이터 중 모델이 올바르게 찾아낸 비율이다.

```text
Recall = TP / (TP + FN)
```

질병 진단에서는 다음 질문에 해당한다.

> 실제 질병 환자 중 모델이 찾아낸 환자는 얼마나 되는가?

앞의 예에서는 질병 환자 10명 중 한 명도 찾아내지 못했다.

```text
TP = 0
FN = 10

Recall = 0 / (0 + 10) = 0
```

재현율은 0%다. 정확도는 99%지만 재현율은 0%다. 두 지표를 함께 보면 이 모델이 실제로는 질병을 전혀 탐지하지 못한다는 것을 알 수 있다.

## 6. F1-score란?

정밀도와 재현율은 서로 반대되는 방향으로 움직이는 경우가 많다.

예를 들어 질병 환자를 놓치지 않기 위해 많은 사람을 질병으로 예측하면 재현율은 높아질 수 있다. 하지만 정상 환자까지 질병으로 예측하면서 정밀도는 낮아질 수 있다.

이때 정밀도와 재현율을 하나의 값으로 평가하기 위해 사용하는 지표가 **F1-score**다.

```text
F1-score = 2 × (Precision × Recall) / (Precision + Recall)
```

F1-score는 정밀도와 재현율의 조화평균이다. 둘 중 하나가 매우 낮으면 F1-score도 낮아진다. 따라서 불균형 데이터에서 두 지표의 균형을 확인할 때 유용하다.

## 7. Balanced Accuracy란?

일반 정확도는 데이터가 많은 클래스의 영향을 크게 받는다. 이를 보완하기 위해 사용할 수 있는 지표가 **균형 정확도(Balanced Accuracy)**다.

균형 정확도는 각 클래스의 재현율을 계산한 뒤 평균을 구한다. 이진 분류에서는 다음과 같이 표현할 수 있다.

```text
Balanced Accuracy
= (양성 클래스 Recall + 음성 클래스 Recall) / 2
```

앞의 예를 다시 살펴보자. 모델은 정상 환자 990명을 모두 올바르게 예측했다.

```text
정상 클래스 Recall = 990 / 990 = 1.0
```

반면 질병 환자 10명은 한 명도 찾지 못했다.

```text
질병 클래스 Recall = 0 / 10 = 0.0
```

균형 정확도는 다음과 같다.

```text
Balanced Accuracy = (1.0 + 0.0) / 2 = 0.5
```

일반 정확도는 99%지만 균형 정확도는 50%다.

| 평가 지표 | 결과 |
| --- | ---: |
| Accuracy | 99% |
| Balanced Accuracy | 50% |
| 질병 클래스 Recall | 0% |

균형 정확도를 확인하면 모델이 한쪽 클래스만 예측하고 있다는 사실을 더 쉽게 발견할 수 있다.

## 8. Python으로 평가 지표 비교하기

다음 코드는 정확도, 정밀도, 재현율, F1-score, 균형 정확도를 함께 계산한다.

```python
from sklearn.metrics import (
    accuracy_score,
    precision_score,
    recall_score,
    f1_score,
    balanced_accuracy_score,
    confusion_matrix
)

# 정상: 0, 질병: 1
y_true = [0] * 990 + [1] * 10

# 모든 환자를 정상으로 예측
y_pred = [0] * 1000

accuracy = accuracy_score(y_true, y_pred)
precision = precision_score(
    y_true,
    y_pred,
    zero_division=0
)
recall = recall_score(
    y_true,
    y_pred,
    zero_division=0
)
f1 = f1_score(
    y_true,
    y_pred,
    zero_division=0
)
balanced_accuracy = balanced_accuracy_score(
    y_true,
    y_pred
)
cm = confusion_matrix(y_true, y_pred)

print("Accuracy:", accuracy)
print("Precision:", precision)
print("Recall:", recall)
print("F1-score:", f1)
print("Balanced Accuracy:", balanced_accuracy)
print("Confusion Matrix:")
print(cm)
```

실행 결과는 다음과 같다.

```text
Accuracy: 0.99
Precision: 0.0
Recall: 0.0
F1-score: 0.0
Balanced Accuracy: 0.5
Confusion Matrix:
[[990   0]
 [ 10   0]]
```

정확도만 확인하면 모델의 성능이 매우 좋아 보인다. 하지만 다른 지표를 함께 확인하면 모델이 질병 클래스를 전혀 예측하지 못한다는 사실을 알 수 있다.

## 9. 어떤 평가 지표가 가장 중요할까?

모든 분류 문제에서 동일한 평가 지표가 가장 중요한 것은 아니다. 어떤 오류가 더 위험한지를 기준으로 지표를 선택해야 한다.

### 9.1 질병 진단

질병 환자를 정상으로 판단하는 것은 위험할 수 있다. 따라서 실제 질병 환자를 얼마나 찾아냈는지를 나타내는 **Recall**이 중요할 수 있다.

```text
중요한 오류: FN
중요한 지표: Recall
```

### 9.2 스팸 메일 분류

정상 메일을 스팸으로 분류하면 중요한 메일을 놓칠 수 있다. 따라서 스팸이라고 예측한 메일이 실제로 스팸인지 확인하는 **Precision**이 중요할 수 있다.

```text
중요한 오류: FP
중요한 지표: Precision
```

### 9.3 금융 사기 탐지

사기 거래를 놓치지 않는 것도 중요하지만 정상 거래를 지나치게 차단해서도 안 된다. 이 경우 Precision과 Recall을 함께 확인하거나 F1-score를 사용할 수 있다.

### 9.4 클래스 비율이 불균형한 분류

각 클래스의 예측 성능을 균형 있게 평가하려면 Balanced Accuracy 또는 클래스별 Recall을 확인하는 것이 좋다.

결국 평가 지표는 단순히 높은 값을 선택하는 문제가 아니다. 모델이 해결해야 하는 문제와 잘못된 예측이 가져오는 비용을 고려해야 한다.

## 10. 분류 모델을 평가할 때 확인할 것

분류 모델을 평가할 때는 정확도 하나만 출력하기보다 여러 지표를 함께 확인하는 것이 좋다.

```python
from sklearn.metrics import classification_report

print(
    classification_report(
        y_true,
        y_pred,
        zero_division=0
    )
)
```

`classification_report()`는 클래스별 Precision, Recall, F1-score와 데이터 개수를 함께 보여준다.

모델 평가 시 다음 항목을 확인할 수 있다.

1. 전체 Accuracy
2. Confusion Matrix
3. 클래스별 Precision
4. 클래스별 Recall
5. 클래스별 F1-score
6. Balanced Accuracy
7. 클래스별 데이터 개수

특히 불균형 데이터에서는 평균값만 확인하지 말고 소수 클래스의 성능을 직접 확인해야 한다.

## 11. 정확도는 필요 없는 지표일까?

정확도에 한계가 있다고 해서 정확도가 필요 없는 지표라는 뜻은 아니다.

클래스별 데이터 수가 비슷하고, 각 클래스의 오분류 비용도 비슷한 문제에서는 정확도가 모델의 전체 성능을 이해하는 데 유용하다.

예를 들어 고양이와 강아지 이미지가 각각 1,000장씩 있고, 두 클래스를 잘못 분류했을 때 발생하는 비용도 비슷하다면 정확도는 비교적 적절한 평가 지표가 될 수 있다.

정확도가 문제가 되는 상황은 다음과 같다.

- 클래스별 데이터 수가 크게 다를 때
- 소수 클래스가 더 중요할 때
- FP와 FN의 비용이 서로 다를 때
- 특정 클래스의 탐지가 모델의 핵심 목적일 때

따라서 정확도를 버리는 것이 아니라 **정확도를 다른 평가 지표와 함께 해석하는 것**이 중요하다.

## 12. 정리

정확도는 전체 데이터 중 모델이 올바르게 예측한 비율이다. 이해하기 쉽고 편리하지만 불균형 데이터에서는 모델의 실제 성능을 충분히 보여주지 못할 수 있다.

핵심 내용을 정리하면 다음과 같다.

> 1. 정확도가 높다고 해서 반드시 좋은 모델은 아니다.
>
> 2. 불균형 데이터에서는 다수 클래스만 예측해도 정확도가 높게 나올 수 있다.
>
> 3. 혼동행렬을 통해 어떤 클래스를 틀렸는지 확인해야 한다.
>
> 4. Precision, Recall, F1-score를 함께 확인해야 한다.
>
> 5. 클래스별 성능을 균형 있게 평가하려면 Balanced Accuracy를 사용할 수 있다.
>
> 6. 문제의 목적과 오분류 비용에 따라 중요한 평가 지표가 달라진다.

모델 평가에서 중요한 것은 가장 높은 숫자를 찾는 것이 아니다. 모델이 실제로 해결해야 하는 문제를 제대로 해결하고 있는지 확인하는 것이 중요하다.

정확도는 모델 평가의 시작점일 수 있지만, 그것만으로 모델의 성능을 결론 내려서는 안 된다.
