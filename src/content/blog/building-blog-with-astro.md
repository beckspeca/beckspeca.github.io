개발하면서 배운 내용을 꾸준히 남길 공간이 필요했다. 글을 쓰는 데 집중할 수 있고, 운영 비용이 들지 않으며, 내가 원하는 대로 디자인할 수 있는 블로그를 만들고 싶었다.

여러 선택지를 비교한 끝에 **Astro + Markdown + GitHub Pages** 조합을 선택했다.

## 왜 Astro를 선택했을까

개발 블로그는 대부분 글과 이미지로 구성된다. 복잡한 서버 기능보다 페이지가 빠르게 열리고 검색 엔진이 내용을 잘 읽을 수 있는지가 더 중요하다.

Astro는 콘텐츠 중심 사이트를 정적으로 생성한다. 브라우저에 불필요한 JavaScript를 보내지 않기 때문에 결과물이 가볍고, Markdown 파일을 게시글로 바로 사용할 수 있다.

이번 블로그에서 중요하게 생각한 기준은 다음과 같다.

- 페이지가 빠르게 열릴 것
- Markdown으로 편하게 글을 작성할 수 있을 것
- 모바일에서도 읽기 좋을 것
- RSS와 사이트맵을 제공할 것
- 별도 서버 비용이 들지 않을 것

## GitHub Pages 자동 배포

블로그 코드는 `beckspeca.github.io` 저장소에서 관리한다. `main` 브랜치에 변경 사항을 올리면 GitHub Actions가 자동으로 Astro 프로젝트를 빌드하고 GitHub Pages에 배포한다.

전체 과정은 단순하다.

```text
Markdown 글 작성
      ↓
GitHub main 브랜치에 push
      ↓
GitHub Actions에서 Astro 빌드
      ↓
beckspeca.github.io에 배포
```

매번 빌드 결과물을 직접 올릴 필요가 없다는 점이 특히 편하다. 글을 작성하고 GitHub에 반영하면 나머지는 자동으로 처리된다.

## 새로운 글을 쓰는 방법

새 글은 `src/content/blog` 폴더에 Markdown 파일을 추가해서 작성한다. 파일 위쪽에는 제목, 설명, 날짜, 태그 같은 정보를 적는다.

```yaml
---
title: '글 제목'
description: '글을 소개하는 짧은 설명'
pubDate: '2026-08-12'
tags: ['Astro', '블로그']
---
```

아직 공개하고 싶지 않은 글에는 `draft: true`를 추가할 수 있다. 초안은 파일로 보관되지만 블로그 목록과 RSS에는 나타나지 않는다.

## 이제부터 기록할 것

블로그를 만드는 것보다 꾸준히 글을 쓰는 일이 더 어렵다. 완벽하게 정리된 지식만 올리려고 하면 시작하기가 힘들기 때문에, 작더라도 직접 경험한 내용을 중심으로 기록하려 한다.

앞으로는 프로젝트를 진행하며 만난 문제와 해결 과정, 새로 배운 기술, 선택에 대한 회고를 남길 예정이다.
